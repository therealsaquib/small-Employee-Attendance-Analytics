# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It used the datetime's existing timezone, floored elapsed minutes before applying the grace check, did not truncate millisecond input to whole seconds, and anchored overnight shifts to the punch-in calendar day. | For a 09:30 shift, 09:40:01 incorrectly returns 0; 09:40:00.900 is not truncated; an early overnight punch is measured against the wrong shift day. | Truncate epoch input to whole seconds, use IST attendance-day/shift-start helpers, and check elapsed seconds `> 600` before flooring minutes. |
| 2 | `compute_work_hours` | Python `round()` uses ties-to-even rather than required half-up rounding. | A duration of 8 hours, 9 minutes gives 8.15, but tie cases can be rounded to the even cent. | Divide integer seconds with `Decimal` and quantize to `0.01` using `ROUND_HALF_UP`. |
| 3 | `compute_overtime` | It did not support overnight shift ends, always returned every positive minute (no 30-minute minimum), and mixed naive and aware datetimes. | A 22:00-06:00 shift punched out at 06:29 reports overtime; an aware punch-out can raise `TypeError`. | Build the shift-end instant in IST on the correct shift date and count floored minutes only when the elapsed time is at least 30 minutes. |
| 4 | `create_employee` | The pre-insert duplicate check races, input fields are unvalidated, `datetime.now()` is local and naive, and the response returns a datetime instead of epoch milliseconds. | Send two simultaneous requests for `EMP0001`; use an invalid email/date or inspect `created_at` type. | Validate the contract with Pydantic, use an atomic unique index and map duplicate-key errors to 409, set an aware UTC server timestamp, and serialize it to epoch milliseconds. |
| 5 | `list_employees` | Skip starts at `page * page_size`, total ignores department, results are unsorted, and page values have no bounds. | Page 1 skips the first page; a department filter reports the unfiltered count; request page 0 or page_size 101. | Use `(page - 1) * page_size`, count the same filter, sort by `emp_code`, and enforce R10 bounds. |
| 6 | `punch_in` | Unknown employees cause a 500; check-then-insert races; `if punched_at` treats zero as missing; date uses local time; status is unrestricted; Mongo `_id` leaks as `id`; punch times are datetimes rather than epoch milliseconds. | Punch for an unknown code, race same-day calls, submit invalid status, send `punched_at: 0`, or inspect the response field types. | Validate the request, derive the IST/R1 date after strict epoch validation, use the unique `(emp_code, date)` index and map duplicates to 409, and serialize epoch milliseconds without identifiers. |
| 7 | `list_attendance` | It loads and sorts the entire collection in Python, sorts only by date, lacks date/status/pagination validation, leaks `_id`, and does not default legacy fields. | Load 100,000 rows, request an invalid date/status, or list a legacy record without `history`. | Apply validated filters, database-side sort/skip/limit/count and projection-shaped serialization; use the date/status indexes and legacy defaults. |
| 8 | `/health` | It always reports success without checking MongoDB. | Stop MongoDB and call `/health`; the starter still returns 200. | Ping MongoDB and return 503 when configuration or the database is unavailable. |
| 9 | Startup | No indexes are created, leaving uniqueness and list/analytics queries unsupported. | Inspect collection indexes after startup or send duplicate concurrent writes. | Create the required employee and attendance indexes idempotently during startup. |
| 10 | Remaining API | Punch-out, regularization, analytics and explain endpoints were absent. | Call any of those documented OpenAPI paths. | Implement the contract endpoints and share aggregation/query builders with explain. |

**Checked and judged fine:** FastAPI runs synchronous route functions in its threadpool, which is appropriate for the synchronous PyMongo client. `load_dotenv()` defaults to `override=False`, so real environment variables win; the implementation makes that behavior explicit.
